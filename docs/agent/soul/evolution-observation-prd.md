## 二、语义对齐（讨论重点）

### 2.1 "演化"的五条线（E 维度，对齐记忆线 G 维度的写法）

| 线 | 定义 | 主要观测量 | 现状 |
|---|---|---|---|
| L1 记忆 | 已有 G1–G5 | 见 growth-observability | **已交付** |
| L2 人格 | self_concept / distill 随漂移改写 | 漂移版本序列、narrative diff、belief 增删 | **无历史（E1）** |
| L3 经验 | life 体验单元累积 | unit 计数曲线（按 source/salience）、虚拟编年史增长、交会折叠率 | 数据 append-only 可回放，**无报表口径** |
| L4 情绪 | affect / valence-arousal 轨迹 | 轮级 delta 序列（已在 experience unit 里）、日级聚合、情绪稳态/极化趋势 | 数据在，**未聚合呈现** |
| L5 剧情 | story 卡片/beat 流转 | 卡片产出-消费曲线、beat 按期兑现率、landmark 按期触发率 | 落盘在，**无观测口径** |

### 2.2 "变成什么样"的可操作定义

三个层次（PRD 认为三者都要，深浅不同）：

1. **轨迹**（过程）：各线指标随时间/对话量的曲线；
2. **时点对比**（结果）：任取两个时间点，soul 的 diff——人格叙事 diff、记忆图形态 diff、经验量/情绪基线 diff；
3. **判据**（结论）：一组可回答 Q 的问题清单（仿 R6.2），例如：人格漂移幅度是否随时间收敛？情绪基线是否漂移？记忆密度与经验量的比例关系？

### 2.3 沿用原则

- **passive telemetry**：观测不改行为、关闭后逐位一致（对齐 memory 线 2.4）；
- persona 版本存档属**旁路追加写入**（旧版本另存，不改覆写主路径）。

## 三、方案分叉（本文档的核心待拍板项）

### D1 长期演化数据怎么产生（三档，可组合）

| 档 | 方式 | 成本 | 产出 |
|---|---|---|---|
| a 真实长跑 | 生产形态挂着跑天/周 | 墙钟慢，但最真 | 真实轨迹 |
| b 回放加速（建议首选） | 扩展现有 `memory_growth_replay.py` 为 **soul 全线回放**：会话驱动 + 每会话手动触发 wander/sleep/drift/story-tick（事件密度当时间轴） | 分钟级跑出"等效数周" | 可控、可重复、可注入剧本 |
| c 时间机器 | 虚拟时钟注入 heartbeat（心跳感知假时间） | 需改 window/interval 判定的时钟源，侵入心跳线 | 能测"活跃时段/每日项"的真日历行为 |

**PRD 建议：b 先行（覆盖 L1–L5），c 仅在需要验证"日历驱动行为"（醒睡、每日 planner、月度漂移按日历）时再立项。**

### D2 范围与顺序

- 选项一：五线齐上（大而全，一次拼完整图景）；
- 选项二（建议）：**先 L2 persona 版本史 + 跨线时间线报告骨架**——L2 是唯一"数据正在丢失"的线（覆写），最急；L3/L4 数据已在，补报表口径即可；L5 最后。

### D3 persona 版本存档形态

- a 每次漂移前全量快照存 `persona/versions/`（简单，文件多）；
- b 版本进 telemetry 事件流水（统一口径，需定 persona 事件 schema）；
- 建议 a+b：快照保全量、事件流记 diff 摘要。

### D4 呈现形态

- 对齐 memory 线现状：**文件 + CLI 报告**（`scripts/soul_evolution_report.py` 产出轨迹曲线文本 + 时点 diff），webui 面板另立需求（同 D5 前例）。

### D5 判定问题清单（Q'1–Q'N）内容

草案：Q'1 人格漂移是否收敛/发散？Q'2 情绪基线是否稳定？Q'3 经验量与记忆密度的比例？Q'4 剧情兑现率随经验的趋势？——**具体清单需与你对齐后定稿**。

## 四、需求草案（敲定分叉后细化，先给骨架）

- R'1 persona 版本存档 + 漂移事件（解 E1）
- R'2 L3/L4/L5 报表口径（数据已在，聚合呈现）
- R'3 soul 全线回放驱动器（D1-b：扩展现有 replay）
- R'4 跨线时间线报告 + 时点 diff（`soul_evolution_report`）
- R'5 回归锁（passive 原则，对齐 R5 手法）

## 五、非目标

- 不改任何演化机制本身（漂移算法/遗忘曲线/擢升门——观测对象不是改造对象，同 D6 前例）；
- 不做 webui 可视化（D4）；
- 不动心跳契约（D1-c 若立项另议）。

## 六、风险

1. 回放加速的"时间密度"失真：每会话触发一次 sleep ≠ 真实昼夜节律，报告需标注"等效时间"语义；
2. persona 快照含完整人格文件，隐私与保留策略对齐 D7 前例（本地、单代上限待定）；
3. L4 情绪聚合口径（轮级→日级）需要定义窗口与加权，先出报告再议。
